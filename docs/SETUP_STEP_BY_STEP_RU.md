# EchoPass: подробная пошаговая инструкция

Документ предназначен для пользователей, которые хотят запустить полный цикл: поднять
локально backend и веб-клиент, подготовить Android-приложение и проверить вход по звуку
от начала и до конца. Инструкция написана предельно подробно и не требует предварительных
знаний о Git или Android SDK.

## 1. Установка необходимых программ

### 1.1 Git
1. **Windows**: скачайте установщик с [git-scm.com](https://git-scm.com/download/win) и
   запустите его. На шаге выбора компонентов оставьте галочки по умолчанию, особенно
   «Git from the command line». В конце установка предложит перезагрузить терминал.
2. **macOS**: выполните `xcode-select --install` либо установите Homebrew и затем
   `brew install git`.
3. **Linux**: используйте пакетный менеджер (`sudo apt install git`, `sudo dnf install git`
   и т. д.).

### 1.2 Node.js и npm
1. Перейдите на [nodejs.org](https://nodejs.org/) и скачайте LTS-версию (устанавливает
   Node.js и npm одновременно).
2. После установки откройте терминал/PowerShell и убедитесь, что команды доступны:
   ```bash
   node -v
   npm -v
   ```
   Обе команды должны вывести номер версии.

### 1.3 Android Studio (включает Android SDK)
1. Скачайте Android Studio с [developer.android.com/studio](https://developer.android.com/studio).
2. Во время установки оставьте отмеченными компоненты **Android SDK**, **SDK Platform Tools**
   и **Android Virtual Device**.
3. После первого запуска Android Studio предложит загрузить SDK — соглашайтесь со всеми
   предложениями.
4. Если вы не хотите ставить Android Studio, можно скачать "Command line tools" и работать
   только из терминала (см. раздел 4).

### 1.4 Дополнительно для Windows
* При первом подключении телефона может потребоваться драйвер производителя. Обычно
  Windows устанавливает его автоматически; при проблемах скачайте драйвер с сайта
  производителя устройства.

## 2. Клонирование репозитория

1. Выберите папку, куда хотите скопировать проект (например, `C:\Projects`).
2. Откройте терминал и выполните:
   ```bash
   cd C:\Projects               # Windows
   git clone https://github.com/<организация>/tokenggwave.git
   cd tokenggwave
   ```
   На macOS/Linux путь будет `/Users/имя/...` или `/home/имя/...`.
3. Проверьте, что появились папки `backend`, `web`, `android`.

## 3. Запуск backend-сервиса

1. Перейдите в каталог backend:
   ```bash
   cd backend
   ```
2. Установите зависимости (делается один раз):
   ```bash
   npm install
   ```
3. Скопируйте файл окружения и при необходимости отредактируйте:
   ```bash
   cp .env.example .env
   ```
   Значения по умолчанию подойдут для локального стенда.
4. Запустите сервер разработки:
   ```bash
   npm run dev
   ```
5. Терминал должен показать `Server listening on http://localhost:4000`. Не закрывайте это
   окно до завершения проверки — сервис нужен фронтенду и приложению.

## 4. Настройка Android SDK (если не использовали Android Studio)

1. Скачайте архив `commandlinetools` с сайта Android Developers для вашей ОС.
2. Распакуйте архив в удобную папку, например `~/Android/cmdline-tools/latest`.
3. Запустите установку необходимых пакетов:
   ```bash
   ./cmdline-tools/latest/bin/sdkmanager \
     "platform-tools" \
     "platforms;android-34" \
     "build-tools;34.0.0" \
     "cmake;3.22.1" \
     "ndk;26.1.10909125"
   ```
4. Примите лицензии:
   ```bash
   ./cmdline-tools/latest/bin/sdkmanager --licenses
   ```
   Для каждого пункта нажмите `y` и затем `Enter`.
5. Запомните путь до папки `Android/Sdk` — он нужен Gradle.

## 5. Подготовка `local.properties`

1. Вернитесь в корень проекта и создайте файл `android/local.properties` (если он еще не
   создан):
   ```bash
   cd /путь/до/tokenggwave
   printf "sdk.dir=%s\n" "/полный/путь/до/Android/Sdk" > android/local.properties
   ```
2. На Windows путь нужно указывать с двойными обратными слэшами, например:
   ```
   sdk.dir=C\:\\Users\\Иван\\AppData\\Local\\Android\\Sdk
   ```
3. Если SDK установлен через Android Studio, путь можно посмотреть в **File → Settings →
   Appearance & Behavior → System Settings → Android SDK**.

## 6. Сборка debug-APK

1. Откройте новое окно терминала (backend продолжает работать в старом) и перейдите в каталог
   Android-проекта:
   ```bash
   cd /путь/до/tokenggwave/android
   ```
2. Выполните сборку:
   ```bash
   ./gradlew assembleDebug      # macOS/Linux
   ```
   или
   ```bash
   gradlew.bat assembleDebug    # Windows
   ```
3. После завершения Gradle сообщит `BUILD SUCCESSFUL`. Готовый файл находится по пути
   `android/app/build/outputs/apk/debug/app-debug.apk`.

## 7. Установка приложения на телефон

### 7.1 Подготовка устройства
1. Откройте на телефоне **Настройки → О телефоне** и 7 раз нажмите «Номер сборки», чтобы
   включить режим разработчика.
2. Перейдите в **Настройки → Система → Для разработчиков** и включите опцию **Отладка по USB**.
3. Подключите телефон к компьютеру кабелем. При первом подключении подтвердите разрешение на
   отладку.

### 7.2 Установка через ADB
1. Убедитесь, что устройство обнаружено:
   ```bash
   adb devices
   ```
   В списке должен появиться серийный номер со статусом `device`.
2. Установите APK:
   ```bash
   adb install -r app/build/outputs/apk/debug/app-debug.apk
   ```
   После сообщения `Success` приложение появится в списке программ.

### 7.3 Альтернативный способ
* В Android Studio откройте меню **Profile or debug APK**, выберите `app-debug.apk` и нажмите
  зеленую кнопку **Run**. Выберите подключенное устройство из списка.

## 8. Запуск веб-клиента и админ-панели

1. В новом окне терминала перейдите в каталог `web`:
   ```bash
   cd /путь/до/tokenggwave/web
   ```
2. Установите зависимости:
   ```bash
   npm install
   ```
3. Создайте файл `.env.local` со строкой:
   ```
   VITE_API_BASE_URL=http://localhost:4000
   ```
4. Запустите фронтенд:
   ```bash
   npm run dev
   ```
5. Откройте браузер и перейдите по адресу, который выведет Vite (обычно
   `http://localhost:5173`). В верхней панели можно переключаться между вкладками
   «Вход по звуку» и «Админ-панель».

## 9. Создание пользователей в админ-панели

1. На вкладке «Админ-панель» заполните поля **User ID** и, при необходимости, **Имя**.
2. Нажмите **«Создать пользователя»**. В списке ниже появится новая строка с
   provisioning-кодом.
3. Нажмите **«Скопировать»**, чтобы сохранить код в буфер обмена. Этот код понадобится на
   телефоне при импорте профиля.
4. Повторите шаги для каждого пользователя, которого хотите протестировать. Все записи
   сохраняются в `backend/data/users.json`.

## 10. Импорт профиля и подготовка токена на телефоне

1. Откройте приложение EchoPass на устройстве.
2. В блоке «Активный профиль» нажмите кнопку **«Импортировать профиль»**.
3. Вставьте provisioning-код, скопированный из админ-панели, и подтвердите.
4. Убедитесь, что выбран нужный профиль: на главном экране показывается `userId`, `kid` и
   подсказка по scope.
5. При необходимости импортируйте несколько кодов — между ними можно переключаться в списке
   профилей.

## 11. Проверка аутентификации по звуку

1. На веб-странице переключитесь на вкладку **«Вход по звуку»** и нажмите **«Войти по звуку»**.
2. Браузер попросит разрешение на микрофон — нажмите **«Разрешить»**.
3. Запустится обратный отсчет и отображение текущего challenge.
4. На телефоне убедитесь, что выбран правильный профиль. Введите challenge (цифрами или hex)
   и нажмите **«Проиграть токен»**. Телефон издаст звук около 2 секунд.
5. Держите устройство в 10–30 см от микрофона ноутбука. Веб-страница должна отобразить
   успешный вход: `Активная сессия: <userId>`.
6. Попробуйте переключиться на другого пользователя (импортировать его код и выбрать профиль)
   и повторите шаги 1–5. Сайт должен показать новую сессию под другим `userId`.

## 12. Частые проблемы и решения

| Симптом | Возможная причина | Что сделать |
|---------|------------------|-------------|
| Vite пишет `Failed to fetch challenge` | Backend не запущен или неверный `VITE_API_BASE_URL` | Проверьте, что backend работает на `localhost:4000`, перезапустите фронтенд после правки `.env.local` |
| `adb devices` не видит телефон | Не включена отладка по USB или нет драйвера | Включите отладку, переустановите драйвер, замените кабель |
| Gradle зависает на `Accepting licenses` | Лицензии SDK не приняты | Выполните `sdkmanager --licenses` и нажмите `y` для всех пунктов |
| Токен не принимается, ошибка `bind32_mismatch` | Прослушивание началось слишком поздно или challenge устарел | Нажмите «Войти по звуку» заново и воспроизведите токен сразу после генерации |
| Ошибка `replay` | Повторно воспроизводится тот же токен | Запустите новую попытку входа (будет новый challenge) |

## 13. Где искать журналы и файлы

* Backend пишет логи в консоль терминала, где запущен `npm run dev`.
* Веб-клиент показывает ошибки в панели разработчика браузера (`F12 → Console`).
* Файл пользователей: `backend/data/users.json` (можно открыть блокнотом для проверки).
* APK после сборки: `android/app/build/outputs/apk/debug/app-debug.apk`.

## 14. Завершение работы

1. Остановите backend и фронтенд, нажав `Ctrl+C` в соответствующих терминалах.
2. При необходимости удалите временные файлы (`npm run clean`, `./gradlew clean`).
3. Чтобы обновить проект до свежей версии, используйте `git pull`.

Следуя этой инструкции, вы получите работающий стенд EchoPass, сможете собрать и установить
Android-приложение и выполнить полную проверку входа по звуку на нескольких пользователях.
