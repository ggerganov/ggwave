# EchoPass / Acoustic Authentication Token (AAT)

Полноценный MVP для авторизации по звуку между веб-сайтом и Android-приложением на базе
GGWave. Репозиторий включает три независимых компонента:

* **`backend/`** — сервис на TypeScript/Express, который выдает challenge, принимает и
  проверяет акустические токены, ведет анти-replay кеш и выпускает серверные сессии.
* **`web/`** — веб-листенер на React/Vite: интерфейс входа по звуку и встроенная
  админ-панель для управления пользователями и их provisioning-кодами.
* **`android/`** — нативное приложение (Kotlin + NDK), генерирующее токены AAT и
  воспроизводящее звуковой пакет через динамик телефона.

## Подготовка окружения

> Нужна сверхдетальная инструкция с комментариями для каждого шага? Смотрите
> файл [`docs/SETUP_STEP_BY_STEP_RU.md`](docs/SETUP_STEP_BY_STEP_RU.md). В нём описаны
> все действия от установки Git и Android SDK до проверки входа по звуку на нескольких
> пользователях.

### 1. Backend (`http://localhost:4000`)

```bash
cd backend
npm install
npm run dev        # режим разработки (ts-node-dev)
# или
npm run build && npm run start
```

Файл `backend/.env.example` содержит все переменные. По умолчанию данные пользователей
хранятся в `backend/data/users.json`; путь можно переопределить переменной `USERS_FILE`.

### 2. Web listener + админ-панель (`http://localhost:5173`)

```bash
cd web
npm install
npm run dev
```

В `.env.local` укажите `VITE_API_BASE_URL=http://localhost:4000`. В браузере откройте
страницу и переключайтесь между вкладками «Вход по звуку» и «Админ-панель» в верхней части.

### 3. Android-приложение

1. Установите Android SDK и пропишите путь в `android/local.properties`
   (`sdk.dir=/путь/до/Android/Sdk`).
2. Соберите debug-APK:
   ```bash
   cd android
   ./gradlew assembleDebug
   ```
3. Готовый файл: `android/app/build/outputs/apk/debug/app-debug.apk`.
4. Установка на устройство:
   * либо перетащите APK в Android Studio (Device File Explorer),
   * либо используйте `adb install app-debug.apk` (предварительно включите режим разработчика).

## Управление пользователями

1. На веб-странице перейдите во вкладку **«Админ-панель»**.
2. Введите `userId` (уникальный идентификатор) и, при желании, отображаемое имя.
3. Нажмите «Создать пользователя» — появится строка provisioning-кода (base64url).
4. Скопируйте код кнопкой «Скопировать» и передайте его владельцу телефона.

Provisioning-код содержит `userId`, `kid`, `scopeId`, `scopeType` и seed в Base64. Его нужно
один раз импортировать на мобильном устройстве. Все созданные пользователи сохраняются в
`data/users.json` и автоматически подхватываются бэкендом.

## Настройка приложения EchoPass на Android

1. Откройте приложение. В блоке «Активный профиль» нажмите **«Импортировать профиль»**.
2. Вставьте provisioning-код из админ-панели и нажмите «Сохранить».
   Приложение проверит код и сохранит профиль локально (SharedPreferences).
3. Для каждого пользователя повторите импорт, когда нужно переключиться.

Во время генерации токена приложение автоматически подставляет `kid`, `scopeId`, `scopeType`
и seed, полученные из кода. Challenge вводится вручную в поле «Challenge».

## Полный сценарий проверки

1. **Запускаем сервисы**: поднять backend (`npm run dev`) и web (`npm run dev`).
2. **Создаем пользователей**: во вкладке «Админ-панель» добавьте, например, трёх пользователей
   и запишите их provisioning-коды.
3. **Импортируем профиль на телефоне**: вставьте код нужного пользователя в приложении.
4. **Производим вход**:
   - во вкладке «Вход по звуку» нажмите «Войти по звуку» и разрешите микрофон;
   - в приложении введите challenge (десятичный или HEX) и нажмите «Проиграть токен»;
   - дождитесь подтверждения: веб-клиент покажет «Активная сессия: userId».
5. **Смена пользователя**: в приложении импортируйте другой код и повторите шаг 4 — на сайте
   должна появиться сессия уже под новым `userId`.

## Архитектура и безопасность

* `/aat/challenge` выдаёт challenge (TTL 60 c, привязка к `bind32`).
* `/aat/verify` проверяет токен: версия, длина, `kid`, `scope`, окно по времени,
  анти-replay по `(kid, scopeId, tslot, nonce)`, HMAC-SHA256 (trunc96).
* `/admin/users` позволяет просматривать и создавать пользователей (для демо без авторизации).
* Сессии — server-side, хранятся в памяти (TTL 15 минут), cookie `Secure+HttpOnly`.
* Android-приложение хранит профиль в `SharedPreferences`; seed можно перенести в Keystore.
